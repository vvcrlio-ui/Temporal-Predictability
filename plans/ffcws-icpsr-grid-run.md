## 技术方案

### G1. 先标定，再定网格（前置，不可跳过）

写一个一次性脚本，用**真实新 ARD** 测量单格成本与峰值内存，覆盖成本曲线的四角：

| 探针 | landmark | N | K | 模型 |
|---|---|---|---|---|
| 1 | lm0 | 1843 | 526（全量） | 全部候选模型各一次 |
| 2 | lm9 | 300 | 5851（全量） | 同上 |
| 3 | lm9 | 1843 | 300（匹配） | 同上 |
| 4 | **lm9** | **1843** | **5851（全量）** | 同上 |

探针 4 是最贵的一格，**它单独决定预算够不够**。

每个探针记录：逐模型墙钟秒数、进程峰值 RSS。**每个探针只跑 1 次重复**，
标定本身控制在 30 分钟内；跑不完的探针如实记为超时，不得估算填充。

**峰值 RSS 的测量方式（2026-08-13 修订，规定死）**：用标准库 `resource`
在标定脚本进程内测量，**不得使用 `/usr/bin/time -l`**——它需要读
`kern.clockrate`，在受限环境下被阻断，而且测的是整个进程树的粗粒度峰值，
无法区分是哪个模型吃的内存。

```python
import resource, sys

def peak_rss_gb() -> float:
    """Peak RSS of this process. Darwin reports bytes, Linux kilobytes."""
    peak = resource.getrusage(resource.RUSAGE_SELF).ru_maxrss
    return peak / 1024**3 if sys.platform == "darwin" else peak / 1024**2
```

`ru_maxrss` 是**单调不减的高水位**，不会随对象释放回落。因此逐模型的增量要用
「拟合后读数 − 拟合前读数」，并在报告中同时给出全程最高水位。
若标定改为多进程执行，另读 `resource.RUSAGE_CHILDREN` 并分别记录。

> 已实测：满量 lm9 的训练矩阵（16,172 列 × 1,843 行 float64）为 **0.222 GB**，
> 纯数据加载后的进程峰值 **0.248 GB**。因此 §G4 的内存阈值考察的是
> **模型内部结构**（random_forest 的 500 棵树、lightgbm 的直方图、
> super_learner 的 5 折折外预测），不是数据本身。

输出写 `reports/ffcws-icpsr-grid-run.md` 的「成本标定」小节，
格式沿用 `plans/ffcws-gpa-horizon-demo.md#b` 那张表。

**标定结果决定 §G2 的取舍**，见 §G4 的缩减规则。

### G2. 网格

**N 网格**（对数间隔，末端加密；末三点须落在上限的 40% / 70% / 100%）：

```
n_grid: [100, 300, 737, 1290, 1843]
```

**K 网格**（逐档不同，**不得用 YAML 锚点共享**）：

```
lm0: [300, 526]    lm1: [300, 1194]   lm3: [300, 2568]
lm5: [300, 3939]   lm9: [300, 5851]
```

匹配值取 **300**：明显小于最小的全量 K（lm0 的 526），
使 lm0 的变量抽样仍有波动（抽 57%），`n_draws` 不失效。
沿用 pilot 的 300 便于与旧结果定性对照。

⚠️ 匹配 K 臂按 E3 是**探索性的"固定测量预算"分析**，
**不得解释为内涵式增益**，其落差按 E3 是低估。

**模型集合**（从 pilot 的 7 个砍到 4 个）：

```
models: [super_learner, ridge, random_forest, lightgbm]
```

理由：`super_learner` 是主预测器（E5b 锁定）；另外三个是 pilot 中各档的包络赢家
（lm0 random_forest、lm1 ridge、lm9 lightgbm），保留它们才能继续报告包络这个
**探索性敏感性分析**。砍掉 `lasso`（pilot 中全档最差且 N=50 时大量
`constant_prediction`）、`extra_trees`（与 random_forest 高度重合）、
`xgboost`（pilot 中未在任何一档进入包络）。

⚠️ 砍模型集合是**在看过 pilot 结果之后**做的决定，与 E4 的"选择时序"问题同源，
必须在报告中如实披露，不得写成"预先指定"。

**重复次数**：`n_seeds: 4`、`n_draws: 4` = 16 次重复，与 pilot 一致。

### G3. 两段式，A 段必须先跑完

引擎按 N 升序执行，**最贵也最重要的满 N 格子排在最后**。
若 12 小时到点被截断，单一 manifest 会正好丢掉主结果。因此拆两份：

**A 段 `panels.landmark.icpsr.endpoints.yaml`** —— 只有满 N：

```
n_grid: [1843]
k_grid: 同 §G2（逐档两个值）
models: 同 §G2（4 个）
prediction_export_cells:
  - {model: super_learner, N: 1843, K: <该档全量>}
  - {model: super_learner, N: 1843, K: 300}
  - {model: ridge,         N: 1843, K: <该档全量>}
  - {model: random_forest, N: 1843, K: <该档全量>}
```

= 5 档 × 2 K × 4 模型 × 16 重复 = **640 次拟合**。这是主结果，**必须跑完**。

**B 段 `panels.landmark.icpsr.curve.yaml`** —— 其余四个 N：

```
n_grid: [100, 300, 737, 1290]
```

= 5 档 × 4 N × 2 K × 4 模型 × 16 重复 = **2,560 次拟合**。
用于判断尾部是否已平，可被截断。

两份都必须通过 `--dry-run`，并在报告里给出各自的
`expected_output_rows` 与 `top_level_model_cells`。

**执行顺序固定为 A → B**，报告中记录 A 段实际耗时。

### G4. 并行与缩减规则

`n_jobs: 4`（M2 的 4 个性能核；panel 层键，默认值即 4）。
`batch_size` 保持默认 20，使 checkpoint 足够密，中断可续。

⚠️ **内存是并行度的约束，不是核数。**满量 lm9 的训练矩阵
16,172 列 × 1,843 行 float64 ≈ 238 MB，四个 worker 各持一份副本再加模型内部结构
（random_forest 500 棵树、lightgbm 直方图）可能触发交换，**一交换就比串行还慢**。
§G1 的峰值 RSS 必须测，并据此定 `n_jobs`：

| 标定测得的单 worker 峰值 RSS | `n_jobs` |
|---|---|
| < 1.5 GB | 4 |
| 1.5–3 GB | 2 |
| > 3 GB | 1，并触发下面的缩减 |

**缩减规则**（按此顺序，直到估算总时长 ≤ 12 小时；每次缩减都要记进报告）：

1. B 段的 `n_seeds` 从 4 减到 2（重复 16 → 8）。**A 段的 16 次重复不得减**——
   它是主结果，且蒙特卡洛噪声的量化依赖它。
2. B 段去掉 `N=100` 这个点（小 N 处 `constant_prediction` 比例最高，信息量最低）。
3. B 段的模型集合减到 `[super_learner, lightgbm]`。
4. 仍不够则只跑 A 段，B 段留待后续，**并在报告中明说尾部是否已平无法判断**。

**不得**为了塞进预算而减少 A 段的任何维度，也不得改用锁定半来"省时间"。

### C1-1（阻塞）预算表把最贵的一格当成了所有格的成本

报告第 57–63 行那张表用探针 4（lm9、满 N、全量 K，四模型 607.461 秒）
作为**每一个同模型组合的上界**。反推得到的 13.50 小时是这么来的：
`640 ÷ 4 = 160` 组 × 607.461 秒 ÷ 2 worker ≈ 13.5 小时。

这个假设有两处失真，第二处是决定性的：

**其一，其余四档的全量 K 远比 lm9 便宜。** 探针 1 已经实测：
lm0 满 N、全量 K=526，四模型合计 **100.684 秒**，是 lm9 的六分之一。
按 K 线性内插（slope = (607.462−100.684)/(5851−526) = 0.0952 秒/source）：

| landmark | K | 四模型合计（秒） |
|---|---:|---:|
| lm0 | 526 | 100.7（实测） |
| lm1 | 1194 | 164.3 |
| lm3 | 2568 | 295.0 |
| lm5 | 3939 | 425.5 |
| lm9 | 5851 | 607.5（实测） |
| **合计** | | **1592.9** |

**其二，K=300 臂被当成了满量 K 的成本。** 探针 3 已经实测：
lm9 满 N、K=300，四模型合计 **199.656 秒**，只有全量 K 的三分之一。
A 段的 640 格里**有一半是 K=300 臂**，这一半被高估了约 3 倍。
五档 K=300 臂合计约 998.3 秒。

修正后：

```
每次重复（5 档 × 2 个 K × 4 模型）= 1592.9 + 998.3 = 2591.2 秒
× 16 次重复 = 41,459 秒 = 11.5 小时（单线程）
÷ 2 worker  = 5.8 小时
```

即使**完全保留**报告原来的悲观假设（五档全量 K 都按 lm9 的 607.5 秒算），
只把 K=300 臂按实测的 199.7 秒计：

```
(5 × 607.5 + 998.3) × 16 = 64,569 秒 = 17.9 小时 ÷ 2 = 9.0 小时
```

**两种算法下 A 段都在 12 小时预算内。** 因此「即使只运行 A 也超过 12 小时」
这一结论不成立，「以破坏 A 段设计为代价进一步砍模型」这个待澄清问题
（报告第 82–83 行）**不必提出**。

   而不是单点，并说明区间来自「K 线性内插」与「全部按最贵档」两种假设。
